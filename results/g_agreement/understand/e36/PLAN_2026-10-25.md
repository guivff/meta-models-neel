## Item freeze and automatic check

Each of the eight registered rows has 12 independently written, feature-bearing
template families, seven fillers and two values: 168 items per row, 1,344 total.
Families 0–5 supply dev and 6–11 supply test. Every family supplies all seven
fillers in both values. Thus every row has 84 dev and 84 test items, with 42 of
each value per split. The fixed split precedes any label check or score.

`build_bank.py` requires the authorized definition packet and only the new E36
author modules. It saves the entire raw bank and its source seal before loading
the automatic checkers. Each checker infers a label from the generated text
without an expected-label argument. Failures preserve the original bank, produce
a FAIL receipt and block launch; they do not trigger replacement or item removal.

After a successful check, CPU tokenization uses the pinned Qwen tokenizer,
without a chat template, special tokens or truncation. The read position is the
last token of the exact prefix. Raw text, tokenized input, private labels and
per-item check evidence remain in ignored `e36/cache/`. A small freeze receipt
binds the bank, definitions, source and automatic-check receipt. GPU input contains
only identity, feature, split, family, text and token IDs; labels stay on the CPU.

Only after this freeze will the operational parent bind the existing frozen
reader candidates. The item authors never receive those candidates or outcomes.
Candidate A/B orientation must exactly match the authorized value definitions.

## Channels and analysis

Capture base-model activations at blocks 42 and 44 for the final read token.
Compute the block-44 probe using the exact source-hashed W1 recipe: five grouped
folds within the six test families, train-fold-only standardization, ridge lambda
0.001 and seed 20261023. The helper's auxiliary donor predictions are unused;
identity donors cannot affect the true held-out predictions.

Score Oracle descriptive candidates and E30 value-word candidates at block 44
with the native paired-log-odds method and empty prefix. Preserve any E30 variants
as separate channels. Average raw log-odds across the frozen phrasings before
AUROC; value A is positive and no score direction is chosen from test outcomes.
Score NLA's W1 pairs at block 42 with its native `<explanation>\n` prefix.

For E15-style continuation, retain the frozen continuation pairs and Oracle's
`- ` prefix. Reuse E15's base-model dev validity rule (AUROC at least 0.80 per
pair) on the new dev items; this selects pairs, never items. Score the complete
test set for every supplied pair and apply the fixed dev selection on CPU.
Missing pairs, failed validity or missing outcomes are explicitly not evaluable.
The four-state H4 denominator is retained; it is not reduced after a failure.

Apply the registered H1–H5 thresholds exactly. H1 requires the Oracle and probe
conditions in the same structure rows. H3 uses a separately sealed E30 R2
eligibility receipt containing the qualifying rows and matching variant IDs,
without historical score values. If R2 was not met, its receipt is unavailable,
or a matching variant is unresolved, H3 is not evaluable. No alternative variant
selection or pooled value-word result is introduced.

## Integrator execution

W-text performs CPU work and commits the request; the integrator alone stages
assets, assigns the pod and launches. The planned execution uses one H200 with
Oracle/capture work followed by NLA. The aggregate maximum is 10,800 GPU seconds,
including setup, warm measurements and any earlier charged attempts. A 180-second
retrieval reserve is inside this cap. The integrator must install and verify an
independent external stop at the corresponding deadline.

The worker requires a bound plan, a PASS freeze receipt, all source and asset
hashes, the integrator assignment and a forecast for every phase. At each batch,
the padded forecast is 1.5 times the remaining work estimate plus the retrieval
reserve. A warm measurement can raise the forecast; one easy batch cannot erase
the conservative phase estimate. A failed gate stops work without retrying or
cutting rows, candidates or channels. There is no local model download or GPU
operation during this build. A held request is not permission to launch.

The integrator records the global run/compute logs when launching, because W-text
is limited to its own experiment directory. Returned raw captures and scores
stay in cache, with a small hashed output seal and CPU analysis report committed
later. No push is performed by W-text.
