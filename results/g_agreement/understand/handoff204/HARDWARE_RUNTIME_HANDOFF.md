# H200/B200 runtime handoff

Authority: cb76843c; E95 policy reused directly from projects/g_agreement/e95/hardware.py (709a34cea). HARDWARE_RUNTIME_REQUEST.json identifies a separate source archive. Existing E81 A4/production, E87/E95 and E99 archives are unchanged. This archive is CPU-tested source only: no B200 smoke, new timing admission or GPU allocation is claimed.

E87/E95 retain worker87.py, with assignment hardware_authority (full cb76843c commit), explicit gpu_type, and analysis_unit_gpu_types mapping every selected row index to that GPU type. Actual CUDA device is checked. E95 calls I-3's validator before model execution. For nla_placebo_only, --reuse-hardware is a CPU-verified JSON map of each selected row to {gpu_type, output_seal_sha256}; assignment.reuse_hardware_sha256 pins it. New placebo hardware must match the reused E87 row. An H200 row cannot receive a B200 floor.

For B200, supply --hardware-receipt pointing to SMOKE_RECEIPT.json and pin its hash in assignment.b200_smoke_receipt_sha256. Assignment.image_digest is an immutable sha256 image digest; stack_sha256 identifies the installed software stack. Receipt must match image, stack, assets and required capabilities. The operator must independently verify those identities before making the assignment. Changed hardware needs new measured timing; never reuse H200 throughput as B200 admission.

Smoke entry point: e87/hardware_smoke.py --inputs DIR --assignment JSON --assets JSON --out NEW_DIR --source-sha E87_SOURCE_SEAL_HASH --input-sha SMOKE_INPUT_SEAL_HASH. The public input directory contains exactly items.json, REFERENCE_RECEIPT.json and SMOKE_INPUT_SEAL.json; use the existing contract.seal helper. Three distinct items each contain exactly id, ids, max_new_tokens and h200. h200 maps text (text mode) or oracle/nla (readers mode) to {raw: original sealed H200 readout}. No labels, targets or private bank fields. REFERENCE_RECEIPT contains status VERIFIED_H200_REFERENCE, gpu_type H200, mode text/readers, items_sha256, source_output_seals, and h200_readout_sha256 mapping each ID to its original sealed H200 member hash. CPU custody verification of those references precedes staging; do not manufacture references from unseen outputs.

Smoke uses unchanged loaders/greedy decoding. Readers smoke captures layers 44/42 and runs Oracle then NLA on all three items. Finite checks and load failures stop the path; differing H200/B200 strings are reported as first differing UTF-8 byte positions, not an equality gate. FIRST_READOUT.json is persisted when the first readout is generated. Its actual file mtime, member hash and name provide first_output_utc evidence in both receipt and terminal seal; no generated readout means unknown. A later failure preserves that evidence. Smoke deadline is creation-based, at most 1800 seconds including a 60-second retrieval reserve, with shared-budget verification required.

The operator must wrap every smoke process exit, staging error and deadline in its existing own-pod stop/custody routine. hardware204.operator_gate(receipt_path, stop_own_pod) invokes that callback and requires EXITED on absent/failed receipt; it does not allocate/terminate via credentials on the pod. STOP_REQUIRED.json records caught runtime failures. A killed process or preflight error may have no marker: absence is never success. No production before verified successful smoke and normal admission.

E81 has a separate hardware_serial81.py entry point around unchanged serial81 batch-1 decoding. Add coordinated_shard_gpu_types with exactly one entry per planned shard and a uniform type, plus analysis_unit_gpu_types={"E81_E90_coordinated_run": GPU_TYPE}. Existing modulo-item sharding can split analysis units, so mixed hardware across its eight shards is rejected. B200 text smoke requires capability text. Use a fresh source-bound serial timing profile and the existing production binder; do not replace the active H200 run or its sealed sources. The E99 stage99 path is not hardware-integrated by this change.

Validation: 19 E87/E95/E99 and hardware CPU tests plus four serial tests pass. Tests cover I-3 policy invocation, reused-row rejection, image mismatch, finite/load failures, verified stop callback and first-output evidence. Live B200 image/reference validation remains the integrator's prerequisite.
