# E40 §149 overnight gate check — 2026-10-26

Recorded before an E40 training/gate pull is available to this worker. This is
an operational entry point for the already registered gate, with no new rule,
threshold, exclusion or scientific computation.

The Integrator's pod ID is assigned later, so the committed command uses a fixed
canonical verified-pull view under E40 cache. Its final/arrays files may be links
to the usual per-pod pull; original bytes and seals are retained. A verified
receipt binds the actual pod, original assignment, output seal and immutable
training request. All original sealed files are checked, including large files.

The registered SAE gate already runs once on the pod. This CPU command checks
its saved moments/counts and exact thresholds; it does not rerun inference.
PASS additionally calls the pre-existing frozen followup.verify_pass helper on
a temporary flat cache view of the same files. FAIL and operational incomplete
runs never call it. A valid operational stop is recorded with no scientific
verdict; any validation or upstream validity failure stops and waits for W-sae.

A global exclusive claim is made before input validation. The command cannot
be retried by changing an output name. Code/dependency validation happens first;
if the committed executable itself cannot be verified/imported, it stops before
reading the pull. All validation failures require owner review, irrespective
of whether a claim could be created.

Outputs are sealed small owner artifacts labelled §149 RUN-BY-INTEGRATOR. The
Integrator commits those bytes and the guard unchanged. Labelling, blind judges,
corpus interpretation and §131 decomposition stay with W-sae in the morning.
No gate PASS is a trigger for an overnight judge or decomposition call.
