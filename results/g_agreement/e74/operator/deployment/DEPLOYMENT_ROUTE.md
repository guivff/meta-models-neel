# E74 runtime handoff route (CPU audit only)

The verified runtime is local to this Mac's Docker engine and the accompanying Docker-save archive. There is no registry upload, provider image URL, allocated pod or remote cache. The archive can be loaded on a host with a Docker daemon after checking its SHA256 and then the image/config ID. Do not assume a standard GPU Pod exposes its host daemon or supports nested Docker.

For the Runpod Pod route currently examined by I-2, the practical distribution route is an explicitly approved registry publication followed by a provider pull. Runpod accepts a custom image name and a registry authentication ID for a private image. Its custom-template guide requires registry access. No publication or credential change has been performed. [Runpod custom templates](https://docs.runpod.io/pods/templates/create-custom-template), [Pod CLI reference](https://docs.runpod.io/runpodctl/reference/runpodctl-remove-pods).

Before that route is usable, I-2 must resolve:

1. The approved registry/account, visibility and retention; push only after explicit authorization. Record and verify the resulting registry manifest digest, which is distinct from our current local config ID. A registry must serve the whole image before allocation; do not build the 209-package environment on a paid GPU under an assumed 900-second deadline.
2. The provider start/control mechanism. The current image deliberately defaults to `python --version` and exits; the launch must override that command with the agreed long-lived supervisor/control entrypoint. No scientific engine is started automatically. The current Dockerfile does not add an SSH server. Runpod documents basic proxied SSH for Pods, but that path has no SCP/SFTP. If I-2 requires full SSH/SCP, add and CPU-verify a separately pinned operations layer plus its start script, record the derived image digest, and rerun the runtime identity/import checks. Do not claim that extension exists now. [Runpod SSH methods](https://docs.runpod.io/pods/configuration/use-ssh).
3. Container disk and transfer capacity. The image has 13,070,541,198 uncompressed bytes; the archive receipt gives its compressed handoff size. Registry compressed layer sizes may differ from this gzip archive. Measure the actual pull/unpack/control setup against the existing 900-second environment/archive allowance and charge all allocated time to E74. The local emulated build time is not a provider pull or native CPU timing estimate.
4. The real 4×B200 quote/availability, current shared budget, provider hard stop and host-driver compatibility with the locked CUDA13.0 runtime and 13.4 compiler components. Then use the unchanged resident-v5 scientific package and fixed 50-fixture smoke. The author's separate 8×B300 documentation does not implement or admit an 8×B300 run here.

A Docker-capable bare host could receive and load the verified local archive without a registry, but that alternative is conditional on I-2 confirming such host access and an allowed provider configuration. It is not an established Runpod deployment route or authorization to allocate another machine.
