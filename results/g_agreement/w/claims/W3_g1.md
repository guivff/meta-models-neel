## Second judge (computation-claim subsample)

Second judge: `anthropic/claude-sonnet-5.5` re-labelled 100 computation claims (claims fixed, labels re-assigned, same context). 5-way label kappa = 0.71 [0.59, 0.83], raw agreement 85%. Among the 91 claims both judges call computation, true/false kappa = 0.86 [0.75, 0.95]. Judge 2 kept the computation type on 91% of claims.

Per reader (5-way): NLA: kappa=0.69 (n=33), Oracle: kappa=0.72 (n=67)

Confusion (judge1 -> judge2, count): computation_false->computation_false: 53, computation_true->computation_true: 32, computation_false->input_false: 6, computation_false->computation_true: 6, computation_true->input_true: 1, computation_true->unverifiable: 1, computation_false->input_true: 1

## Notes

- Readouts: G1 test states, condition genuine, sample 0 (gen_id g1|olens|*|s0, g1|nla|*|s0); the prompt shown to the judge is the full chat string from the target rows; the model's actual greedy answer is the target row's raw_output (correct on 32/32 test states by the item regex).
- G4 repeat samples (8 test states x 2 readers x samples 1-2) judged the same way: results/g_agreement/w/claims/W3_g4_repeats.md (NLA input 25% [20, 30], computation 42% [19, 67]; Oracle input 38% [19, 61], computation 40% [10, 69]).
- Second-judge subsample: 100 of 167 computation claims by seed 0 (random.Random(0).sample); the second judge saw the fixed claim list and reassigned labels (type and truth), so the 5-way kappa also absorbs type moves (computation -> input on 7/100).
- API usage above covers G1 + G4 + the second-judge pass (judge_usage.json); the usage file also counts the 4-readout smoke test, which the cache reused.
- S4 input format for the pod builder: one JSON row per sample with state_item_id, reader, sample_idx, text, candidates, answer, actual_answer (+ optional prompt_text, question, gen_id, module, family, direction, alpha); see the docstring of projects/g_agreement/w_claims/judge.py.
