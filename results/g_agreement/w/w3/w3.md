# W3 — claim precision on the S4 samples (input vs computation claims), with the G1 numbers

Judge: `google/gemini-3.8-flash` via `projects/g_agreement/w_claims/judge.py` (Track C; adapted from Michael Kenney's `nla-consistency/scripts/claim_judge.py`). Precision = true / (true + false) pooled over claims, 8 samples per state; CI = state-level bootstrap (1000 resamples, seed 0); unverifiable claims excluded. On the ERROR states the model's greedy answer is wrong: computation claims are scored against the model's ACTUAL answer (the judge's label) and separately against the puzzle's CORRECT answer (judge-anchored relabel: computation_false AND the text names the correct symbol, not the actual). Counts: the model is correct, so 'actual' = the value. A text-only check (which candidate the claim names) sits next to each judge number.
