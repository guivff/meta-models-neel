# V4 — human labels for claim precision

**Sheet:** `results/g_agreement/v/human_labels.csv` (300 rows, written 2026-10-12 by
`projects/g_agreement/w_claims/human_sheet.py`, seed 0).

**Where the claims come from.** The judge (`google/gemini-3.8-flash`, adapted from Michael Kenney's
`nla-consistency/scripts/claim_judge.py`; see `projects/g_agreement/w_claims/judge.py`) split every Oracle Lens and NLA
free-text readout of the G1 test states (32 states × 2 readers, `claims_g1.jsonl`, 404 claims) and the G4 repeat
samples (8 states × 2 readers × samples 1–2, `claims_g4.jsonl`, 214 claims) into ≤ 12 atomic claims and labelled each
`input_true / input_false / computation_true / computation_false / unverifiable`. The 300 rows are stratified over
reader (Oracle, NLA) × claim type (input, computation) × judge truth (true, false), equal quotas with water-filling
when a stratum is short (taken / available): Oracle input true 29/29, Oracle input false 40/46, Oracle computation true
40/64, Oracle computation false 39/111, NLA input true 39/74, NLA input false 39/205, NLA computation true 35/35, NLA
computation false 39/43. Rows are shuffled. S4 claims (8 samples per state on the error and counts states, after the
pod) will top up the two capped strata when they exist; rerun `human_sheet.py` with both claim files and `--n 300`.

**Columns.** `claim_id` (gen_id#k), `reader`, `item_id`, `prompt_text` (exactly what the model saw, chat template
included), `model_answer_or_key` (the model's greedy answer, the answer key and the two candidates),
`claim_text`, `claim_type` (judge's: input or computation), `judge_label`, `human_label` (fill), `notes` (free).

**How to label.** Judge each claim against the prompt, and, for computation claims, against the model's actual answer
(fall back to the key when no actual answer is shown). Put `true`, `false` or `unverifiable` in `human_label`
(`t/f/u`, `1/0` and full labels such as `input_false` are also accepted). If you think the judge's claim type is
wrong, write the full label of the right type (e.g. `input_false` on a row typed `computation`); the scorer counts
that as a type disagreement and still compares the truth value. Leave rows blank to skip them.

**Scoring (when the sheet returns).**

    .venv/bin/python -m projects.g_agreement.w_claims.kappa results/g_agreement/v/human_labels.csv \
        --out results/g_agreement/v/v4_kappa.json

prints judge–human Cohen's κ on the truth value (overall with a 1,000-resample bootstrap CI, per reader, per claim
type, per reader × type), the number of type disagreements, and W3 precision on the human subset (human truth vs the
judge's on the same rows; item-level bootstrap, seed 0). Then rerun W3 with the human subset reported alongside
`results/g_agreement/w/claims/W3_g1.md`. Pre-registered use (PREREG_WV V4): κ and the W3 rerun on return; no threshold
on κ was pre-registered, so report it as a calibration number for the judge-based precision table.

**Second-judge check already available.** On a 100-claim subsample of computation claims, `anthropic/claude-sonnet-5.5`
re-labelled the judge's claims: 5-way κ = 0.71 [0.59, 0.83]; true/false κ = 0.86 [0.75, 0.95] among the 91 claims both
judges typed as computation (`results/g_agreement/w/claims/W3_g1.md`).
