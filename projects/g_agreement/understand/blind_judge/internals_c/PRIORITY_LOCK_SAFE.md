# Lock-safe administrative priority recovery

The original controller can SIGSTOP a queued process while that process has a pending flock on the pacing lock. The kernel can grant the lock after the controller releases it even while the worker is stopped. The queue then stalls without a physical reservation.

This replacement never edits worker source, rate intervals, cooldowns, ledgers, bank allocations or scientific rules. It preserves the same registered phase order and own-process ownership checks. While holding the pacing lock, after stopping only a queued unreserved own worker, it checks whether that process has the pacing lock file open. If so, it resumes that SAME process before releasing the lock and leaves its ticket unchanged; no send slot can be claimed while the controller still holds the lock. It only leaves a worker parked when the pacing FD is absent. Probe failure resumes immediately and fails closed. Unknown or inflight reservations are never stopped.

At the single startup recovery boundary, an exact saved original controller state identifies its prior paused own workers. A paused own worker with the pacing FD open is resumed only after verifying its module/phase identity, zero unresolved physical cost, loaded and paid deadlines, no402 latch, and a fresh source-bound supplementary route/privacy/funding/global-accounting receipt published before recovery. No request is resent and no worker is restarted. Existing primary identity is retained even if its first request becomes inflight while the controller starts. The old administrative controller must be stopped first so two controllers never compete. All original controller source/state history is preserved separately.
